# 개인화 리서치 뉴스레터 PRD (Web)

## 1. Detailed product description

### 1.1 제품 한 줄 소개

사용자가 **원하는 토픽/주제**를 입력하면, 서비스가 **추가 질문으로 맥락을 더 수집**하고, 그 결과를 바탕으로 **에이전트가 리서치**하여 **개인화된 뉴스레터를 이메일로 전달**하는 웹 서비스.

### 1.2 문제 정의

* 신기술(예: LLM, 에이전트, MLOps, 로보틱스, 보안, 칩 등) 흐름이 빠르지만, 사용자는

  * “어디서부터 무엇을 읽어야 하는지” 결정 비용이 크고
  * 관심사(업무/취미/학습 수준/시간)에 맞는 큐레이션을 얻기 어렵고
  * 깊이 있게 읽을 가치가 있는 링크를 매번 선별하기 힘듦

### 1.3 목표(Goals)

| 목표          | 설명                            | 측정(예시)               |
| ----------- | ----------------------------- | -------------------- |
| 개인화 정확도     | 사용자가 ‘내 취향/수준’에 맞다고 느끼는 비율 향상 | 만족도(👍) |
| 정보 탐색 시간 절감 | 사용자가 탐색-선별에 쓰는 시간을 줄임         | “5분 안에 핵심 파악” 응답률    |
| 신뢰 가능한 리서치  | 요약뿐 아니라 근거(링크/출처)를 제공         | 링크 클릭률, 출처 신뢰도 피드백   |

### 1.4 비목표(Non-goals)

* 실시간 뉴스 속보 서비스(초단위 업데이트) 지향
* 완전한 자동 투자/의료/법률 조언 제공
* 페이월(유료기사) 무단 복제/전재

### 1.5 핵심 가치 제안(Value Proposition)

* **뉴스레터 개인화**: “주제 입력 → 추가 질문 → 뉴스레터 생성”으로 독자 맥락을 빠르게 파악
* **에이전트 기반 리서치**: 단순 요약이 아니라, 계획-탐색-검증-요약의 반복으로 품질을 끌어올림
* **메일로 정리된 결과물**: 읽기 흐름이 깨지지 않게 사용자 이메일 inbox로 배송 + 웹 아카이브 제공

### 1.6 사용자 플로우(요약)

1. 사용자가 웹에서 주제 입력(한국어)
2. 시스템이 개인화를 위한 추가 질문(한국어) 생성 (대화형 X 추가 질문 UI로 답변 수집)
3. 사용자가 답변(한국어)
4. LangGraph 에이전트가 리서치 수행(소스 수집 → 중요도/신뢰도 판단 → 요약/구성)
5. 뉴스레터 생성(한국어) 및 이메일 발송
6. 사용자는 피드백(👍/👎, “더 깊게/더 쉽게”) 제공 → 다음 발송에 반영

### 2.2 레퍼런스에서 뽑는 설계 원칙

* (Google Alerts) **입력 마찰 최소화**: 주제만 넣어도 바로 가치 제공
* (Feedly/Inoreader) **노이즈 제거가 곧 가치**: 중복/저품질 소스 필터링이 핵심
* (Techmeme/TLDR) **뉴스레터는 ‘구조’가 제품**: 제목-섹션-요약-링크의 리듬
* (Perplexity) **출처와 추론 과정의 투명성**: 링크, 근거, 제한사항을 명시

## 3. Core features and specifications

> **모든 사용자 입력/출력(UI, 이메일, 알림, 버튼, 시스템 메시지)은 한국어로 제공**한다.

### 3.1 기능 범위(MVP)

| 구분                     | 포함 | 비고                |
| ---------------------- | -- | ----------------- |
| 웹 UI                   | ✅  | Next.js 기반        |
| 회원/로그인                 | ✅  | 이메일 기반(간단)        |
| 주제 입력                  | ✅  | 자유 텍스트(한국어)       |
| 추가 질문 생성(필수)           | ✅  | 개인화를 위한 3~7개 질문   |
| 답변 수집                  | ✅  | 폼 형태(한국어)       |
| LangGraph 에이전트 리서치(필수) | ✅  | deepagents 포함     |
| 뉴스레터 생성                | ✅  | 한국어, 섹션형          |
| 이메일 발송                 | ✅  | 기본 발송(온디맨드 또는 예약) |
| 아카이브                   | ✅  | 웹에서 지난 뉴스레터 열람    |
| 피드백                    | ✅  | 👍/👎 + 한 줄 코멘트   |

### 3.2 핵심 기능 상세

#### A) 주제 입력

* **입력(한국어)**: 사용자가 관심 주제를 자유롭게 입력
* 예시

  * “에이전트 기반 코딩 도구(2026 트렌드)”
  * “LLM 안전성과 레드팀 기법”
  * “쿠버네티스에서 MLOps 운영 베스트프랙티스”

**요구사항**

* 최소 5자 이상
* 금칙어/악성 콘텐츠 필터링(기본 안전장치)

#### B) 추가 질문 생성 (Must Feature #1)

* 목표: 개인화에 필요한 맥락을 빠르게 확보
* 생성 방식(가이드)

  * **목표**(학습/업무/투자/취미)
  * **난이도**(초급/중급/고급)
  * **관심 범위**(산업/기술/오픈소스/학계)
  * **시간**(읽기 가능 시간, 원하는 길이)
  * **선호 소스**(블로그/논문/뉴스/레퍼런스 문서)
  * **관심 있는 하위 토픽**(특히 집중하고 싶은 하위 관련 토픽들)

**UI 예시(한국어)**

* “이 주제를 왜 알고 싶으신가요? (업무/학습/취미/기타)”
* “현재 이해 수준은 어느 정도인가요? (초급/중급/고급)”
* “한 번에 읽을 수 있는 분량은 어느 정도가 좋나요? (3분/5분/10분/15분+)”
* “특히 관심 있는 하위 토픽 2~3개를 골라주세요.” (토픽1/2/3.../ 또는 사용자 직접 작성)

**수용 기준(Acceptance Criteria)**

* 질문은 3~7개
* 질문/선택지/도움말 모두 한국어
* 사용자가 답변하지 않아도(스킵) 최소한의 뉴스레터 생성 가능

#### C) 리서치 에이전트 (Must Feature #2: LangGraph + deepagents)

* 입력: (주제 + 추가 질문 답변)
* 출력: 뉴스레터에 들어갈 **검증된 요약 + 링크 + 추천 이유**

**에이전트 단계(권장 파이프라인)**

1. 리서치 계획 수립(서브쿼리 생성)
2. 소스 수집(공개 웹, RSS, 공식 블로그/문서 우선)
3. 중복 제거 및 신뢰도/관련도 스코어링
4. 핵심 주장/근거 추출(링크 포함)
5. 뉴스레터 구조로 재구성(요약 → 핵심 링크 → ‘왜 중요한가’)
6. 사실성 점검(모호/불확실하면 명시)

**가드레일(필수)**

* 링크/출처 없는 단정적 주장 금지(불확실 시 “확실하지 않음” 표기)
* 저작권/페이월 콘텐츠는 **직접 인용/전재 금지**(짧은 인용 + 링크 중심)
* 특정 기업/기술 홍보성 자료는 표시(“홍보/스폰서 가능성”)

#### D) 뉴스레터 생성 및 이메일 발송

**뉴스레터 포맷(한국어, 권장 템플릿)**

* 제목: “[주제] 이번 주 핵심 업데이트 (YYYY.MM.DD)”
* 1. TL;DR (3~6줄)
* 2. 핵심 이슈 3~5개 (각각 요약 + 링크 1~3개)
* 3. Deep Dive 1개 (조금 긴 설명 + 추가 읽을거리)
* 4. 다음에 파볼 질문(사용자 맞춤)
* 5. 출처 목록(링크)

**발송 옵션(초기 가정)**

* MVP: 온디맨드 발송(“지금 생성/발송”)
* 이후: 주간/격일/매일 예약 발송

**수용 기준**

* 메일 제목/본문/CTA 모두 한국어
* 링크는 원문으로 연결
* 동일한 주제에 대해 재발송 요청 시, 최신 소스 우선 반영

#### E) 피드백 루프

* 사용자 입력(한국어)

  * “이번 뉴스레터가 도움이 되었나요? 👍/👎”
  * 선택: “어떤 점이 좋았/아쉬웠나요?”
* 시스템 동작

  * 다음 리서치에서 소스/난이도/분량 조정

### 3.3 핵심 화면(웹)

| 화면       | 주요 요소(한국어)                    |
| -------- | ----------------------------- |
| 홈        | 주제 입력창, 예시 토픽, 로그인            |
| 질문 화면    | 추가 질문 3~7개, 스킵/제출             |

| 결과(아카이브) | 뉴스레터 본문, 링크, 공유, 피드백          |
| 설정       | 관심 토픽 목록, 발송 빈도, 분량, 선호/차단 소스 |

### 3.4 성공 지표(KPIs) 제안

| 퍼널  | 지표               | 목표(초기 예시)       |

* 사용자가 귀찮아하면 질문 수를 자동 축소(피로도 관리)

## 5. User persona and scenarios

### 5.1 타깃 페르소나

* 얼리어답터
* 신기술에 관심이 많고, 새로운 기술을 발빠르게 따라잡고 싶은 사람

### 5.2 대표 시나리오

#### 시나리오 1: ‘주간 AI 에이전트 동향’ 캐치업

* 입력(사용자): “2026년 에이전트 프레임워크 트렌드”
* 추가 질문(시스템): “업무 목적이신가요, 학습 목적이신가요?”
* 답변(사용자): “업무(프로토타입 제작), 난이도 중급, 10분 분량”
* 결과(시스템):

  * TL;DR: 5줄
  * 핵심 이슈: 멀티에이전트 오케스트레이션, 평가(Evals), 도구 호출 안정성 등
  * Deep Dive: LangGraph 중심 설계 패턴
  * 링크: 공식 문서/블로그 위주

#### 시나리오 2: ‘내 스택(Next.js)과 연결된 기술만’ 보고 싶음

* 입력(사용자): “LLM을 웹 서비스에 붙이는 최신 방법”
* 추가 질문(시스템): “현재 사용 중인 기술 스택이 있나요?”
* 답변(사용자): “Next.js, Supabase, 중급, 보안 이슈도 포함”
* 결과(시스템):

  * 섹션에 “웹 보안 체크리스트”가 포함
  * “Supabase 연동 패턴”이 우선 배치

#### 시나리오 3: ‘너무 긴 글 싫음(3분 컷)’

* 입력(사용자): “AI 칩/가속기 동향”
* 추가 질문(시스템): “원하는 분량은?”
* 답변(사용자): “3분 요약”
* 결과(시스템):

  * 핵심 3개 이슈만 제공
  * 링크는 1~2개로 최소화

## 6. Technical stack

> 요청된 스택(Next.js, Supabase, LangGraph, deepagents)을 중심으로 **실행 가능한 권장 구성**을 제안한다. (세부 DB 스키마/저장 설계는 본 문서 범위에서 제외)

### 6.1 아키텍처(개요)

| 레이어                 | 권장                                                     | 역할                         |
| ------------------- | ------------------------------------------------------ | -------------------------- |
| Frontend            | Next.js (App Router)                                   | 주제 입력, 질문 UX, 아카이브, 설정     |
| Auth                | Supabase Auth                                          | 이메일 기반 로그인/세션              |
| DB                  | Supabase Postgres                                      | 사용자/주제/답변/뉴스레터 로그/피드백 저장   |
| Backend             | Next.js Route Handlers + (필요시) Supabase Edge Functions, FastAPI (for LangGraph Agent) | 리서치 에이전트 처리, 스케줄 발송 트리거      |
| Agent Orchestration | LangGraph                                              | 리서치 단계(계획-탐색-검증-요약) 그래프 구성 |
| Agent Toolkit       | deepagents                                             | 검색/수집/요약 등 도구 레이어          |
| Email               | 트랜잭셔널 메일 서비스(예: Resend/SendGrid 등)                     | 뉴스레터 발송, 템플릿               |
| Observability       | Sentry/Logflare + PostHog(선택)                          | 에러/성능/사용 지표                |

### 6.2 운영 관점 권장사항

* **스케줄링**: 주간/매일 발송은 크론(예: Vercel Cron 또는 Supabase 스케줄러/워크플로우)으로 트리거
* **캐싱/중복 방지**: 동일 사용자/주제 조합에 대해 최근 N시간 내 생성 요청은 재사용 옵션 제공
* **레이트 리밋**: 악성 요청 및 비용 폭주 방지(사용자별/시간별)
* **콘텐츠 품질**: 소스 신뢰도 가중치(공식 문서/학회/주요 매체 우선), 중복 제거
* **법적/윤리**: 원문 대량 전재 금지, 링크 중심 + 짧은 인용, 로봇 배제 표준 존중

### 6.3 MVP 구현 난이도 낮추는 팁

* 초기에는 “온디맨드 발송(지금 생성)”만 제공 → 스케줄링은 P1로
* 소스 수집은 RSS/공식 블로그/문서 중심으로 시작 → 점진 확장
* 개인화는 “추가 질문 3~5개 + 피드백 1개”로 단순화 → 학습형 프로필은 P2
