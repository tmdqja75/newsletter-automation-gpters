## 브라우저가 토큰을 너무 많이 먹고 있었어요 🌐

AI 에이전트가 실제 업무에 쓰이기 시작하면서 예상치 못한 병목이 생겼어요. 바로 웹 브라우징이에요. 에이전트가 웹페이지를 탐색할 때마다 날 것의 HTML을 통째로 읽어야 했는데, 이 과정에서 엄청난 양의 토큰이 소모됐거든요. 직접 에이전트를 업무에 활용하던 개발자 Ismail이 이 문제를 해결하기 위해 만든 것이 바로 Pickle이에요. (출처: https://news.ycombinator.com/item?id=49260102)

### Pickle이 뭔가요?

Pickle은 AI 에이전트 전용으로 설계된 브라우저예요. 일반 브라우저처럼 탭, 검색 기록, 북마크 같은 기능을 다 갖추고 있지만, 페이지 로딩 방식이 근본적으로 달라요. HTML 원문 대신 컴팩트한 구조화 데이터로 페이지를 전달해요. 덕분에 에이전트가 웹페이지를 읽는 데 소모하는 토큰이 기존 대비 약 32배 줄어들었다고 해요. (출처: https://news.ycombinator.com/item?id=49260102)

### 정책 게이트(Policy Gate)가 핵심이에요

Pickle의 또 다른 핵심 기능은 정책 게이트(Policy-Gated Actions)예요. 쉽게 말하면 에이전트가 마음대로 할 수 있는 것과 사람의 승인이 필요한 것을 명확하게 나누는 시스템이에요.

- 특정 도메인 차단 설정 가능
- 구매처럼 민감한 행동은 사용자 승인 필요
- 모든 액션이 로그로 기록되어 언제든 에이전트 동작을 확인하고 직접 개입 가능 (출처: https://news.ycombinator.com/item?id=49260102)

모델 강도에 따라 행동 범위도 자동으로 조절돼요. 약한 로컬 모델은 한 번에 한 스텝씩만 행동해서 환각(hallucination)이나 잘못된 엘리먼트 ID 생성을 방지하고, 강한 모델은 여러 스텝을 미리 계획할 수 있어요.

### 왜 지금 주목해야 하나요?

에이전트가 브라우저를 쓰는 건 이미 흔한 일이 됐어요. 하지만 그 비용과 통제 가능성은 아직 해결되지 않은 문제예요. Pickle은 이 두 가지를 정면으로 다뤄요.

32배의 토큰 절감은 단순한 비용 절감 그 이상의 의미예요. 컨텍스트 한도 안에서 더 많은 작업을 처리할 수 있고, 로컬 모델처럼 약한 모델도 웹 에이전트로 쓸 수 있는 가능성이 열려요. 또 크로스 세션 페이지 엘리먼트 기억 기능 덕분에 에이전트가 같은 페이지를 재방문할 때 버튼 위치를 다시 찾아야 하는 낭비도 없어져요.

API 키 없이 바로 다운로드해서 쓸 수 있고, Claude Desktop, Cursor, VS Code, Codex CLI 원클릭 연동도 지원해요. (출처: https://news.ycombinator.com/item?id=49260102)

### 시사점

에이전트 인프라 레이어가 조용히 성숙해지고 있어요. LLM 자체의 성능 경쟁 뒤에서, 에이전트가 실제로 작동하는 환경을 더 효율적이고 안전하게 만드는 도구들이 속속 등장하고 있죠. Pickle 같은 툴이 많아질수록, 지금 당장 강력한 모델이 아니어도 실용적인 에이전트를 구성할 수 있는 시대가 가까워져요.
