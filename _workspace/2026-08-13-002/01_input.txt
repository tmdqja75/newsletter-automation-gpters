# 🥒 에이전트가 브라우저를 쓸 때 토큰이 새는 문제, Pickle이 막아드립니다

AI 에이전트에게 브라우저를 맡겨본 적 있으신가요? 뭔가 검색해오라고 시켰더니, 정작 유용한 결과보다 HTML 태그 수백 줄을 읽어들이는 데 토큰을 다 써버리는 경험이요. Pickle은 바로 이 문제를 직접 겪은 개발자가 만든 AI 에이전트 전용 브라우저예요. (출처: https://news.ycombinator.com/item?id=49260102)

### 에이전트는 왜 브라우저를 못 다루나요?

일반 브라우저(크롬, 파이어폭스 등)는 철저히 사람 중심으로 설계됐어요. 탭, 북마크, CSS 렌더링, 60fps 스크롤 — 에이전트에겐 전부 불필요한 짐이죠. 에이전트가 웹페이지에 접근하면 날것의 HTML을 그대로 읽어야 하는데, 이게 토큰을 엄청나게 소모해요.

Pickle 개발자(HN 사용자 ismail_h)는 이 문제를 몸소 겪고 해결책을 직접 만들었어요. Pickle은 페이지를 HTML 대신 압축된 구조화 데이터로 변환해 에이전트에게 전달해요. 실제 테스트에서 토큰 사용량이 최대 32배 감소하는 효과를 확인했답니다. (출처: https://news.ycombinator.com/item?id=49260102)

### Pickle의 핵심 기능 3가지

1. 정책 기반 접근 제어 (Policy-Gated Actions)

에이전트가 뭐든 마음대로 하게 두면 불안하죠. Pickle은 정책 게이트(Policy Gate)라는 개념으로 이 문제를 해결해요. 차단할 도메인을 지정하거나, 구매처럼 민감한 액션은 사람의 승인을 거치도록 설정할 수 있어요. 모든 행동은 로그로 남고, 사용자가 언제든 에이전트 대신 직접 개입할 수 있어요. 마치 인턴 사원에게 업무를 맡기되, 큰 결재는 팀장 도장이 필요한 것처럼요. (출처: https://news.ycombinator.com/item?id=49260102)

2. 모델 강도에 따른 자동 경로 설정 (Auto-Routing by Model Strength)

약한 로컬 모델과 강력한 클라우드 모델을 동시에 쓸 수 있어요. 로컬 모델은 한 번에 하나의 액션만 선택하도록 제한해 환각(hallucination)을 방지하고, 강한 모델은 여러 단계를 한 번에 계획할 수 있어요. 덕분에 API 키 없이도 로컬 모델로 바로 시작할 수 있고, Claude Desktop, Cursor, VS Code, Codex CLI와도 원클릭으로 연동돼요. (출처: https://news.ycombinator.com/item?id=49260102)

3. 에이전트 특화 생산성 기능들

- 공유 노트북: 사용자와 에이전트가 함께 쓰고 읽을 수 있는 메모 공간
- 페이지 요소 메모리: 이전에 방문한 페이지의 버튼 입력창 위치를 기억해, 재방문 시 다시 찾을 필요가 없음
- 세션 간 히스토리 검색: 과거 세션의 작업 내역을 검색 가능
- 브라우징 모드(Browsing Modes): 리서치, 학습, 쇼핑 등 용도별로 에이전트 행동 방식을 다르게 설정하는 페르소나 기능 (출처: https://news.ycombinator.com/item?id=49260102)

### 에이전트 전용 브라우저라는 새로운 카테고리

사실 이 방향으로 움직이는 건 Pickle만이 아니에요. Cloudflare도 최근 에이전트 전용 브라우저 Kitesurf를 발표했어요. Chromium이 CPU 메모리를 과도하게 소모한다는 점, 에이전트에겐 탭이나 CSS 픽셀 완벽도보다 토큰 효율 보안 확장성이 더 중요하다는 점을 동일하게 지적했죠. (출처: https://blog.cloudflare.com/kitesurf)

두 프로젝트 모두 같은 문제를 다른 방향으로 풀고 있어요. Cloudflare는 Rust와 WebAssembly로 서버사이드 헤드리스 브라우저를 만들었고, Pickle은 로컬에서 실행되는 데스크톱 브라우저로 접근했어요. 에이전트가 웹에 접근하는 방식 자체가 새롭게 정의되는 시점이라는 신호죠.

### 왜 지금 이게 중요할까요?

에이전트 시대에 브라우저는 더 이상 사람을 위한 도구가 아니에요. 에이전트가 실제 업무를 수행하는 공간이 되어가고 있죠. 그런데 도구가 사람 중심으로 설계되어 있으면, 에이전트는 비효율적으로 작동하고 비용도 급등해요.

Pickle은 그 틈새를 정확히 파고든 프로젝트예요. API 키도 필요 없고, 로컬 모델로 바로 쓸 수 있어서 진입장벽도 낮아요. 에이전트에게 브라우저를 맡기고 싶었지만 토큰 비용이 걱정됐던 분들이라면, 한번 직접 써볼 만한 도구예요.
